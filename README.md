# Протоколист — ассистент по ведению протоколов встреч (Android)

Нажали «Запись» на совещании — получили готовый протокол: резюме, участников, ключевые вопросы,
решения, задачи с ответственными и сроками, открытые вопросы. Идея и сценарий — как у Plaud AI,
но без отдельного устройства: запись идёт с микрофона телефона.

## Что умеет

- **Запись в фоне.** Foreground-сервис с уведомлением (пауза / закладка / стоп), работает при выключенном экране.
- **Закладки.** Отмечайте важные моменты прямо во время записи — модель получает их как приоритетные.
- **Устойчивость.** Запись режется на части по 25 минут и пишется в OGG/Opus (~11 МБ в час); если процесс убит,
  запись восстанавливается из файлов при следующем запуске.
- **Расшифровка + протокол в фоне.** WorkManager: ждёт сети, повторяет при сбоях, продолжает с последней расшифрованной части.
- **6 шаблонов:** общая встреча, планёрка/daily, клиент/переговоры, интервью, совещание руководства, лекция.
  Протокол можно пересоздать другим шаблоном без повторной расшифровки.
- **Просмотр:** вкладки «Протокол» и «Расшифровка» с метками времени; тап по строке — перемотка записи; задачи отмечаются галочкой.
- **Экспорт:** поделиться текстом (Markdown), PDF (A4, без сторонних библиотек), копирование в буфер.
- **Разделение по говорящим (диаризация).** Включается в настройках; расшифровка получает подписи «Спикер A / B…».
  Нажмите на говорящего, чтобы задать имя — оно заменится во всей расшифровке и учитывается при (пере)создании протокола
  (участники и ответственные подставляются по именам). Любую реплику можно поправить: текст, говорящий, удаление.
- **Редактирование протокола.** Кнопка с карандашом: правка резюме, участников, повестки, ключевых вопросов, решений,
  задач (ответственный, срок, приоритет), открытых вопросов; добавление и удаление пунктов. Можно написать протокол с нуля.
- **Поиск** по названию и содержимому протоколов. Тёмная и светлая темы.
- **Приватность:** всё хранится на устройстве; ключи — в EncryptedSharedPreferences.

## Как запустить

1. Android Studio Ladybug (2024.2) или новее, JDK 17.
2. `File → Open` → папка `Protokolist`. Студия сама скачает Gradle 8.9 и зависимости.
3. Запустите на устройстве или эмуляторе с Android 10+ (minSdk 29).
4. В приложении: **Настройки** → укажите API-ключи (см. ниже) → **Сохранить**.

> Gradle Wrapper jar в архив не включён (нет сети при сборке). Android Studio работает по `gradle-wrapper.properties`;
> для командной строки выполните один раз `gradle wrapper`.

### Сборка APK без Android Studio (GitHub Actions)

1. Создайте репозиторий на GitHub и загрузите в него содержимое папки проекта (вместе с `.github`).
2. Вкладка **Actions** → **Build APK** → **Run workflow** (или просто сделайте push в `main`).
3. Через 5–10 минут откройте завершённый запуск и скачайте артефакт **Protokolist-debug-apk** — внутри `app-debug.apk`.
4. Если сборка упала, откройте лог шага «Build debug APK» и пришлите ошибку.

## Подключение ИИ

| Этап | Что нужно | По умолчанию |
|---|---|---|
| Расшифровка | OpenAI-совместимый `POST {base}/audio/transcriptions` | `https://api.openai.com/v1`, модель `whisper-1` |
| Протокол | OpenAI-совместимый `chat/completions` **или** Claude (`/v1/messages`) | `gpt-4o-mini` / `claude-sonnet-5-5` |

Адреса и модели редактируются — подойдёт любой совместимый сервис (в том числе свой Whisper-сервер за HTTPS).
Если ключ для протокола не указан и сервис тот же, что для расшифровки, используется один ключ.
Для моделей `gpt-4o-*-transcribe` метки времени грубые (один сегмент на часть); у whisper-совместимых — построчные.

## Архитектура

```
audio/    RecorderService (запись, части, уведомление), RecorderState, PlayerController (ExoPlayer, склейка частей)
data/     Room (Meeting), Repository, SettingsStore (зашифрованные ключи), модели и Protocol (kotlinx.serialization)
ai/       AiClient (расшифровка, протокол; длинные встречи — через конспекты фрагментов), Prompts, Templates
work/     ProcessingWorker — конвейер «расшифровка по частям → протокол», прогресс пишется в БД
ui/       Compose: Home, Record, Meeting, Settings, Export (Markdown/PDF), тема
```

Весь прогресс обработки хранится в БД (`Status`: RECORDING → RECORDED → QUEUED → TRANSCRIBING → SUMMARIZING → DONE / ERROR),
экраны просто наблюдают за ним через Flow.

## Известные ограничения и что делать дальше

- **Код не компилировался и не запускался** на устройстве: при подготовке не было Android SDK. Возможны мелкие ошибки
  импортов/версий при первой сборке — Android Studio их подсветит.
- Диаризация идёт отдельно по каждой 25-минутной части записи, поэтому метки «A/B» в разных частях могут не совпасть
  с одними и теми же людьми — исправляйте переименованием (двум меткам можно задать одно имя) или правкой реплик.
  Для работы нужна модель с диаризацией (`gpt-4o-transcribe-diarize` или совместимый сервис с полем `speaker`).
- «Пересоздать протокол» и «Расшифровать заново» затирают ручные правки протокола — приложение об этом предупреждает.
- В редакторе протокола нет перестановки пунктов.
- Нет облачной синхронизации и резервного копирования; `allowBackup=false`.
- Запись только с микрофона: звонки и звук других приложений Android не отдаёт.
- Строки интерфейса зашиты в код на русском; для локализации вынесите их в `strings.xml`.
- Перед публикацией: подпись релиза, политика конфиденциальности (аудио уходит стороннему API), согласие участников на запись.
